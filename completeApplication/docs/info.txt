				> Einarbeitung in React Konzepte: Komponenten, Routing
					- React ist eine JavaScript-Bibliothek für die Entwicklung von Benutzeroberflächen (User Interfaces, UIs).
					- React ermöglicht die Erstellung von wiederverwendbaren UI-Komponenten, die modular und flexibel sind.
					- Sie basiert auf dem Konzept des virtuellen DOM, was effizientere Aktualisierungen und bessere Performance erlaubt.
					- Besonders geeignet für Single-Page-Applications (SPAs) und komplexe Web-UIs.
					- React ist das Framework, JSX ist eine bequeme Schreibweise, um mit React zu arbeiten:
					- Einführung in JSX und Komponenten
						JSX: Eine Erweiterung von JavaScript, mit der man HTML-ähnlichen Code direkt im JavaScript schreiben kann.
						Komponenten: Wiederverwendbare UI-Bausteine, die die Struktur der Anwendung modularisieren.
						Funktionale Komponenten: JavaScript-Funktionen, die JSX zurückgeben.
						Klassenkomponenten: Komplexere Komponenten mit eigenen Zuständen (State) und Lebenszyklusmethoden.
					- State und Props:
						State: Interne Daten einer Komponente, die sich im Laufe der Zeit ändern können.
						Props: Daten, die von einer Elternkomponente an eine Kindkomponente übergeben werden.
						🎯 Analogie
						State ist wie das Gedächtnis einer Komponente.
						Props sind wie Informationen von außen, die die Komponente erhält.
					-Verwaltung des Komponentenstates mit useState
						useState-Hook: Ermöglicht die Verwendung von State in funktionalen Komponenten.
							Gibt ein Array mit zwei Werten zurück:
							- Den aktuellen State-Wert.
							- Eine Funktion zur Aktualisierung des States.
							- State-Updates sind asynchron und führen zu einer neuen Render-Ausführung der Komponente.
					- 📬 Übergabe von Daten mit Props
						Props werden von einer Elternkomponente an eine Kindkomponente weitergereicht.
						Sie funktionieren ähnlich wie Funktionsargumente.
						Die Kindkomponente greift über das props-Objekt auf diese Daten zu.
						Innerhalb der Kindkomponente sind Props unveränderlich (read-only) – sie können dort nicht direkt verändert werden.
					- React Router ist eine Bibliothek für die Navigation in React-Anwendungen.
						Sie ermöglicht, dass verschiedene URLs unterschiedliche Komponenten anzeigen – ohne die Seite neu zu laden.
						Das Ergebnis ist eine Single-Page Application (SPA) mit dynamischer Navigation.
						🔧 Wichtige Komponenten
							BrowserRouter: Nutzt die History API des Browsers für sauberes Routing.
							Routes: Definiert alle verfügbaren Routen.
							Route: Verknüpft eine URL mit einer bestimmten Komponente.
							Link / NavLink: Erzeugt klickbare Links, um zwischen Seiten zu wechseln.

				- REST (Representational State Transfer) ist ein Architekturstil für verteilte Systeme.
				- RESTful APIs sind Schnittstellen, die den Zugriff auf Ressourcen über das HTTP-Protokoll ermöglichen.
				- HTTP-Methoden (GET, POST, PUT, DELETE) werden verwendet, um Operationen auf Ressourcen durchzuführen (lesen, erstellen, aktualisieren, löschen).
				- Die Kommunikation erfolgt in der Regel über JSON (JavaScript Object Notation).
			- Restulf APIs in Spring Boot: ERSTELLUNG VON CONTROLLERN UND MAPPING VON ENDPUNKTEN 
				- Controller: Eine Klasse in Spring Boot, die Anfragen entgegennimmt und verarbeitet.
				- Endpunkte: URLs, die mit bestimmten HTTP-Methoden und Ressourcen verknüpft sind.
				- Annotationen:
					@RestController: Markiert eine Klasse als Controller.
					@GetMapping, @PostMapping, @PutMapping, @DeleteMapping: Verknüpfen Methoden mit HTTP-Methoden und Endpunkten.
					@PathVariable: Extrahiert Werte aus der URL.
					@RequestBody: Extrahiert Daten aus dem Anfragekörper (meistens JSON).
				- Umgang mit HTTP-Anfragen und Antworten
					📤 Anfragen (Requests) Enthalten 
						die HTTP-Methode (GET, POST, etc.), 
						die URL 
						optional: Daten im Anfragekörper.
								  Header, die zusätzliche Informationen liefern (z. B. Authentifizierungstoken).

					📥 Antworten (Responses) Enthalten 
						einen HTTP-Statuscode (z. B. 200 OK, 404 Not Found), 
						Header 
						optional: Daten im Antwortkörper (meistens JSON).

					🧰 Spring Boot
						Verwendet Objekte wie HttpServletRequest und HttpServletResponse, um auf Anfragen und Antworten zuzugreifen.
						Bietet Annotationen wie @ResponseStatus, um den Statuscode einer Antwort festzulegen.

			- Einarbeitung Datenbanken
				ÜBERBLICK ÜBER NoSQL-DATENBANKEN
				- Nicht-relationale Datenbanken, die Daten nicht in Tabellen, sondern in flexibleren Strukturen speichern (z.B. Dokumente, Key-Value-Paare, Graphen).
				- Vorteile von NoSQL:
					- Flexibilität: Anpassung an sich ändernde Datenstrukturen.
					- Skalierbarkeit: Einfache Verteilung auf mehrere Server.
					- Performance: Schnelle Lese- und Schreibvorgänge.
				- Nachteile von NoSQL:
					- Keine ACID-Transaktionen (wie in relationalen Datenbanken).
					- Komplexere Abfragen können schwieriger sein.

				MongoDB – DIE DOKUMENTENORIENTIERTE DATENBANK
				- Eine beliebte NoSQL-Datenbank, die Daten in BSON-Dokumenten (ähnlich wie JSON) speichert.
				- Dokumente können verschachtelte Strukturen und Arrays enthalten.
				- Flexibles Schema: Dokumente in derselben Collection können unterschiedliche Felder haben.
				- Leistungsstarke Abfragesprache: Ermöglicht komplexe Suchen und Filter.
				- Einrichtung:
					- Installation:
					- MongoDB kann von der offiziellen Website heruntergeladen und installiert werden: https://www.mongodb.com/
					- MongoDB Compass: Eine grafische Benutzeroberfläche (GUI) zum Verwalten und Durchsuchen deiner MongoDB-Datenbank.
					
			INTEGRATION VON MongoDB in SPRING BOOT
				- Spring Data MongoDB: Ein Modul, das die Integration von MongoDB in Spring Boot-Anwendungen vereinfacht.
					Vorteile:
						- Reduziert Boilerplate-Code.
						- Bietet eine einfache und typische Schnittstelle zur Datenbank.
						- Unterstützt CRUD-Operationen und komplexe Abfragen.
					Konfiguration:
						Hinzufügen der Spring Data MongoDB-Abhängigkeit zur pom.xml 
						Konfigurieren der Verbindung zur MongoDB-Datenbank in der application.properties-Datei.
				REPOSITORIES – DER ZUGANG ZU DEINEN DATEN
					Repositories sind Schnittstellen, die den Zugriff auf Daten in der Datenbank ermöglichen.
					Sie erweitern das CrudRepository-Interface von Spring Data.
					Spring Data erstellt automatische Implementierungen für grundlegende CRUD-Operationen (Create, Read, Update, Delete).
						Create: save(entity) – Speichert ein neues oder aktualisiert ein bestehendes Objekt in der Datenbank.
						Read: findById(id), findAll() – Liest ein Objekt anhand seiner ID oder alle Objekte aus der Datenbank.
						Update: save(entity) – Aktualisiert ein bestehendes Objekt in der Datenbank.
						Delete: deleteById(id) – Löscht ein Objekt anhand seiner ID aus der Datenbank.
					Du kannst eigene Methoden für benutzerdefinierte Abfragen hinzufügen.

Was bedeutet „Nebenwirkung“ in diesem Kontext?
	- In der funktionalen Programmierung (worauf React teilweise basiert) ist eine „Nebenwirkung“ (engl. side effect) 
	  jede Aktion, die außerhalb der Funktion selbst etwas verändert oder mit der Außenwelt interagiert.
	- Beispiele 
		Daten von einer API laden (fetch)
		In die Konsole schreiben (console.log)
		DOM direkt manipulieren
		Timer setzen (setTimeout, setInterval)
		Lokalen Speicher lesen/schreiben (localStorage)
		Event Listener registrieren
		Zustand außerhalb der Funktion verändern

	- useEffect wird verwendet, um Nebenwirkungen auszuführen :
		useEffect(() => {
			// Effekt-Code
				return () => {
				// Optional: Cleanup-Code //Wird vor dem nächsten Effekt oder beim Unmount der Komponente ausgeführt.
							 Wichtig bei z. B. Timern oder Event Listenern, um Speicherlecks zu vermeiden.
				};
		}, [abhängigkeiten]); 

		abhängikeiten Steuert, wann der Effekt erneut ausgeführt wird.
			Wenn leer ([]): Effekt wird nur einmal nach dem ersten Render ausgeführt.
			Wenn Werte enthalten sind: Effekt wird jedes Mal ausgeführt, wenn sich einer dieser Werte ändert.
